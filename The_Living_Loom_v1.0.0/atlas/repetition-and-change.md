# Repetition and change

Repetition is not one operation.

It can replay an identical pattern, expose a difference that was already present, accumulate charge, update a model through repeated tests, reactivate memory, or change the configuration when loops intersect. The word “again” tells us almost nothing until we identify what is being updated.

In its limited-access reading of a source using fictional architecture, the Loom tracks repeated site encounters, revived memory, and variation. The ordinary rival is contextual cueing amplified by narrative interpretation. The Loom preserves both while extracting the structural question.

Open question: in a repeated cycle, which state variable changes even when the visible event looks the same?
