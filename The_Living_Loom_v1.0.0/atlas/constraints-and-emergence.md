# Constraints and emergence

Calling every change “transformation” destroys the information needed to design it.

A failed fragment can become construction material. A supposed constraint can be bypassed by changing the problem frame. The same blocker can change function and become an enabler. A useful fraction can be extracted while surrounding debris remains. These are different operations with different risks.

The countercase is simple: cutting a real load-bearing constraint can destroy the target. A Gordian move is only useful when the discarded relation is not essential to the desired invariant.

Open question: before changing a constraint, can we state whether we intend to remove it, route around it, reuse it, reverse its role, or select through it?
