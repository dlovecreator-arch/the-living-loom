# A connection under challenge

## The attractive collapse

The Loom provisionally classifies four limited-access source situations as distinct constraint operations. These labels are original analysis, not Dana's terminology or a reconstruction of her wording. At first, all four can be called stories of transformation:

- failed memory fragments become material for a new composition;
- an intractable knot is approached by making its perceived constraints moot;
- a structure that prevented change later enables it;
- nutrients are parsed from debris before the debris clears.

The shared label feels elegant. It is also too coarse to be useful.

## The four operations

### Recomposition

The first operation reuses the failed fragment itself. What looked like a dead end becomes an input to a new construction. The component remains present, but its membership in a larger pattern changes.

### Bypass

The second operation changes the problem frame so a represented constraint no longer governs the route. The knot is not painstakingly solved from within its original topology. The danger is cutting a relation that was actually essential.

### Functional inversion

The third operation keeps the same structural element but changes its role. The blocker becomes an enabler under a new configuration. This is not removal and not merely reinterpretation.

### Selective extraction

The fourth operation leaves debris as debris while a receiver discriminates and takes up the usable fraction. Cleanup may happen later. The unwanted component is neither reused nor converted.

## Why the distinction matters

If these operations are merged, a designer can apply the wrong intervention:

- trying to reuse what should be removed;
- cutting what must remain load-bearing;
- waiting for a blocker to invert when no configuration can change its function;
- assuming contamination itself is valuable because value exists within a mixed field.

## The rival unification

A higher-order model can still group all four as changes in constraint relation. That abstraction is useful only if it preserves the subtype. It explains that the agent is not simply overpowering a fixed obstacle, while the subtype determines what action is actually warranted.

## What would justify a deeper merge

A future source would need to show the same component moving through two or more of these roles under specified conditions—for example, debris first selected around, then recomposed, then made enabling. Shared imagery or the word “transformation” would not be enough.
