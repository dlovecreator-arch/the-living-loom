# What you can do with the Loom

Choose a question first. Bring only the material needed to answer it. The examples below describe uses of the method, not products already implemented or guaranteed outcomes.

| Your purpose | Bring | The useful output | Check the boundary |
| --- | --- | --- | --- |
| Understand a difficult passage | The actual passage and relevant media | Close reading, strongest interpretation, rival and unresolved language | Missing text stays missing |
| Trace an idea across several works | Source passages and dates where known | A genealogy of what stays stable and what changes | Reposts do not count as independent recurrence |
| Explore symbolic connections | Exact forms, sequence and proposed relation | A tested relationship or a clearly marked lead | Resemblance does not establish intention or a cipher |
| Design a tool or process | A source distinction and a concrete use problem | A proposal with inputs, transformation, output and failure cases | The design is yours; it is not attributed backward to the author |
| Make a decision | Your goal, constraints and available evidence | Separation of preference, feasibility, permission, capacity and uncertainty | A compelling interpretation is not evidence for an unavailable fact |
| Preserve a powerful insight | The question, evidence, insight and remaining alternatives | A compact resumption note with a next useful move | A summary must retain a route back to evidence |
| Work with disagreement | Both readings and their source anchors | Shared observations, real disagreement and a discriminating question | Do not force reconciliation for neatness |
| Build a private knowledge system | A complete permitted export and retrieval contract | Source-aware search, current views and recoverable lineage | The public starter alone does not contain the private archive |

## A small application template

State the question. Identify the source-derived distinction you want to use. Describe the target situation separately. Explain which relationship transfers, which substrate or condition changes, and what would count as failure. Name an observable outcome before claiming success. Retain the result whether it supports or challenges the design.

An application can be useful even when it does not settle the source's metaphysics. A failed application can reveal a bad transfer without invalidating the source itself. Keep those judgments separate.

## Return without starting over

When you pause, preserve five things: the question, the best conditional answer, its decisive evidence, the live alternative, and the next useful action. Add the version or source boundary if it matters. That is enough to support a careful return without making every conversation a maintenance project.
